# 耗电统计数据来源说明

本文说明“耗电统计调试”里展示的几类数据来源，以及它们在统计中的具体用途。

## 采样记录

耗电统计由 `PowerUtilizationCurve` 定时采样写入 `battery_io` 表。正常亮屏状态下约每 3 秒记录一次，熄屏时会停止定时采样，并在熄屏事件发生时额外写入一条熄屏记录。

每条记录主要字段如下：

- `time`：采样时间，毫秒时间戳。
- `temperature`：电池温度。
- `status`：电池状态，如放电、充电、未充电。
- `io`：换算后的电流，单位 mA。
- `voltage`：电压，单位 V。
- `remaining_mah`：当前剩余电量，单位 mAh。
- `screen_on`：采样时屏幕状态。
- `capacity`：当前电量百分比。
- `package` / `mode`：当时前台应用和性能模式。

## 剩余 mAh

当前优先使用：

```text
BatteryManager.BATTERY_PROPERTY_CHARGE_COUNTER
```

可选来源：

```text
BatteryManager.BATTERY_PROPERTY_CHARGE_COUNTER
/sys/class/power_supply/bms/charge_counter
/sys/class/power_supply/battery/charge_counter
/sys/class/power_supply/bms/charge_now
/sys/class/power_supply/battery/charge_now
/sys/class/power_supply/bms/energy_now
/sys/class/power_supply/battery/energy_now
```

用途：

- 写入 `battery_io.remaining_mah`。
- 计算亮屏耗电和熄屏耗电时，优先使用相邻两条记录的 `remaining_mah` 差值。
- 计算预计剩余亮屏时间时，作为“剩余电量”使用。

如果 `remaining_mah` 不可用，亮屏/熄屏耗电会回退到整数电量百分比差值，但短周期误差会明显变大。

## 电量百分比

优先使用：

```text
/sys/class/power_supply/bms/capacity_raw
```

可选来源：

```text
/sys/class/power_supply/bms/capacity_raw
BatteryManager.BATTERY_PROPERTY_CAPACITY
```

用途：

- 页面顶部显示当前电量。
- 写入 `battery_io.capacity`。
- 当 `remaining_mah` 不可用时，用相邻记录的 `capacity` 差值估算亮屏/熄屏耗电。
- 作为 `capacity_raw` 的校验基准，如果 `capacity_raw` 和系统整数电量差距超过 5%，会回退到系统整数电量。

注意：整数百分比只有 1% 粒度，短时间统计不适合只依赖它。

## 电池容量

优先使用：

```text
/sys/class/power_supply/battery/charge_full_design
/sys/class/power_supply/bms/charge_full_design
```

继续 fallback：

```text
/sys/class/power_supply/battery/charge_full
/sys/class/power_supply/bms/charge_full
PowerProfile.getBatteryCapacity()
```

用途：

- 页面显示电池容量。
- 将 mAh 消耗换算成百分比：

```text
消耗百分比 = 消耗 mAh * 100 / 电池容量 mAh
```

- 当没有直接剩余 mAh 时，用系统百分比估算剩余 mAh：

```text
估算剩余 mAh = 电池容量 mAh * 当前电量百分比 / 100
```

`charge_full_design` 更接近设计容量，`charge_full` 更接近当前健康状态下的满充容量；两者取舍会影响 mAh 与百分比之间的换算。

## 电流

当前来源：

```text
BatteryManager.BATTERY_PROPERTY_CURRENT_NOW
```

用途：

- 写入 `battery_io.io`。
- 计算应用记录里的平均电流。
- 计算周期内平均电流。
- 计算亮屏平均功耗。
- 作为预计剩余亮屏时间的分母。

电流原始值会按照用户校准的单位换算：

```text
显示/统计电流 mA = 原始 CURRENT_NOW / 当前单位
```

默认单位来自自动判断，也可以由用户在耗电统计里校准。单位错误会直接影响平均功耗和预计剩余亮屏时间。

## 电压

当前来源：

```text
ACTION_BATTERY_CHANGED / BatteryManager.EXTRA_VOLTAGE
```

用途：

- 写入 `battery_io.voltage`。
- 将电流换算成功率：

```text
功率 W = 电流 mA * 电压 V / 1000
```

- 当剩余电量来源是 `energy_now` 时，将能量换算为 mAh：

```text
mAh = Wh / 电压 V * 1000
```

## 屏幕状态

当前写入字段：

```text
battery_io.screen_on
```

用途：

- 区分亮屏样本和熄屏样本。
- 应用记录只统计 `screen_on = 1` 的样本。
- 周期统计把相邻两条记录之间的时间归属给上一条记录的屏幕状态。
- 亮屏耗电和熄屏耗电同样按上一条记录的 `screen_on` 归属。

当前代码对亮屏时间做了保护：如果上一条记录是亮屏，单段时间最多按 10 秒计入，避免应用进程被挂起后把一大段断档误算成亮屏。

## 周期统计计算

周期统计来自 `BatteryHistoryStore.getCycleStats()`。

### 时间相关记录

周期统计里和时间有关的值都来自 `battery_io.time`，不会直接读取系统的“屏幕使用时间”统计。

内部会按时间升序遍历所有采样记录：

- 第一条记录的 `time` 作为本轮统计的 `startTime`。
- 最后一条记录的 `time` 作为本轮统计的 `endTime`。
- `sampleCount` 是本轮统计参与计算的采样条数。
- `recordedTime` 是所有相邻采样间隔累加后的记录跨度。
- `screenOnTime` 是被归属为亮屏的记录时间。
- `screenOffTime` 是被归属为熄屏的记录时间。

这里的“记录跨度”不是自然时间总长，而是按相邻两条采样记录计算出来的有效跨度。如果应用进程被系统挂起、服务被杀、定时器被暂停，中间没有采样记录，统计只能根据断档前后的两条记录推断。

相邻两条记录的时间归属规则是：

```text
当前段时间 = 当前记录 time - 上一条记录 time
当前段状态 = 上一条记录 screen_on
```

也就是说，一段时间属于亮屏还是熄屏，取决于这一段开始时那条记录的 `screen_on` 值。

亮屏段有额外保护：

```text
亮屏计入时间 = min(当前段时间, 10000ms)
```

这样做是为了避免亮屏时进程被挂起后，下一次恢复采样时把几十分钟断档全部算成亮屏。熄屏段目前不做 10 秒封顶，因为熄屏后本来就会停止定时采样，只依赖熄屏事件和下一次恢复采样来估算熄屏跨度。

因此，如果看到亮屏时间明显不对，优先排查：

- `screen_on` 记录是否符合实际屏幕状态。
- 相邻记录时间间隔是否稳定接近 3 秒。
- 是否存在大量小于 1 秒的重复采样。
- 是否存在很长时间没有采样的断档。
- 应用进程是否被系统后台限制或杀掉。

### 亮屏/熄屏时间

对相邻两条记录计算时间差：

```text
duration = 当前 time - 上一条 time
```

归属规则：

- 上一条 `screen_on = 1`：计入亮屏时间。
- 上一条 `screen_on = 0`：计入熄屏时间。

亮屏段会做上限保护：

```text
亮屏计入时间 = min(duration, 10000ms)
```

### 亮屏/熄屏耗电

优先用 mAh 差值：

```text
consumedMAH = 上一条 remaining_mah - 当前 remaining_mah
```

只有两条记录都处于放电或未充电状态，并且 `remaining_mah` 正常下降时才计入。

如果没有可用 mAh，则显示整数百分比下降：

```text
drop = 上一条 capacity - 当前 capacity
```

### 平均电流和亮屏平均电流

平均电流：

```text
avgCurrent = 所有放电样本 abs(io) 的平均值
```

亮屏平均电流：

```text
screenOnAvgCurrent = screen_on = 1 的放电样本 abs(io) 平均值
```

亮屏平均功耗显示时会结合平均电压：

```text
screenOnAvgPower = screenOnAvgCurrent * screenOnAvgVoltage / 1000
```

## 预计剩余亮屏时间

预计剩余亮屏时间使用：

```text
预计剩余亮屏时间 = 剩余 mAh / 亮屏平均电流 mA
```

其中：

- 剩余 mAh 优先来自 `BatteryManager.BATTERY_PROPERTY_CHARGE_COUNTER`。
- 如果没有直接剩余 mAh，会使用电池容量和当前百分比估算。
- 亮屏平均电流来自 `screen_on = 1` 的放电样本。

因此，预计值主要受两件事影响：

- 剩余 mAh 来源是否可靠。
- 电流单位是否校准正确。

## 应用记录

应用记录来自 `BatteryHistoryStore.getAvgData()`，查询条件包括：

```sql
status in (DISCHARGING, NOT_CHARGING)
package != ''
screen_on = 1
group by package, mode
```

也就是说，应用记录只统计亮屏期间的前台应用样本。熄屏时的前台应用不会进入应用记录。

应用记录显示的是该应用前台期间采样到的平均电流和温度，不表示这些耗电全部由该应用造成。

## 调试页应该怎么读

调试页里每一项都会展示：

- 当前使用的来源。
- 原始值。
- 换算值。
- 说明。
- 可选来源。

排查建议：

- 预计亮屏时间明显偏大：优先看电流原始值和单位换算是否偏小。
- 亮屏/熄屏耗电不合理：看剩余 mAh 来源是否可用，以及 `remaining_mah` 是否随放电稳定下降。
- 电量百分比跳变大：看是否回退到了整数百分比。
- 容量换算不符合设备标称：看当前使用的是 `charge_full_design`、`charge_full` 还是 `PowerProfile`。
